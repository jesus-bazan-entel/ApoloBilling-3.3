1. Vision General de la Arquitectura

ApoloBilling es una plataforma de facturacion de telecomunicaciones en tiempo real para entornos VoIP. La arquitectura implementa un Session Border Controller (SBC) completo con los siguientes componentes:

2. Componentes del Sistema

2.1 Kamailio / dSIPRouter

🔒 Session Border Controller :5060 UDP/TCP

Kamailio actua como el punto de entrada principal para todo el trafico SIP externo. dSIPRouter proporciona una interfaz de gestion adicional.

Funcion Modulo Descripcion
SIP Routing drouting Enrutamiento dinamico basado en prefijos (LPM)
ACL por IP permissions Control de acceso por direccion IP
NAT Traversal nathelper Manejo de clientes detras de NAT
Media Proxy rtpengine Integracion con RTPEngine para relay de media
Autenticacion auth_db Autenticacion digest contra MySQL
Registrar usrloc Registro de ubicacion de usuarios

Tablas MySQL (Kamailio)

Tabla Proposito
dr_gateways Gateways SIP (type=8 carriers, type=9 PBX)
dr_gw_lists Grupos de gateways para failover
dr_rules Reglas de enrutamiento saliente
address ACL basada en IP (peers confiables)

2.2 RTPEngine

🎧 Media Proxy Control :2223 RTP :10000-20000

RTPEngine maneja todo el trafico de media (audio/video) actuando como proxy/relay entre los endpoints.

Funciones de RTPEngine
+------------------+ +------------------+ +------------------+ | Endpoint A | | RTPENGINE | | Endpoint B | | (Telefono IP) | | | | (Carrier) | +------------------+ +------------------+ +------------------+ | | | | RTP (G.711) | RTP (G.729) | | --------------------> | ------------------> | | | [Transcoding] | | RTP (G.711) | RTP (G.729) | | <-------------------- | <------------------ | | | | Capacidades: - Codec Transcoding (G.711 <-> G.729, Opus, etc.) - DTMF Interworking (RFC2833 <-> SIP INFO <-> In-band) - SRTP <-> RTP Bridge (encripcion/desencripcion) - ICE/STUN/TURN para NAT traversal - Recording (captura de media) - Symmetric RTP handling

Configuracion Principal

# /etc/rtpengine/rtpengine.conf [rtpengine] interface = internal/127.0.0.1;external/10.10.22.4 listen-ng = 127.0.0.1:2223 port-min = 10000 port-max = 20000 log-level = 6

2.3 FreeSWITCH

📞 PBX / Media Server Internal :5080 External :5062

FreeSWITCH maneja todas las funciones de PBX incluyendo IVR, voicemail, conferencias y grabacion.

Perfiles SIP de FreeSWITCH

mod_xml_curl - Autenticacion Dinamica

FreeSWITCH consulta al Backend Rust para autenticar dispositivos SIP:

POST /api/v1/freeswitch/directory Content-Type: application/x-www-form-urlencoded sip_auth_username=1001 sip_auth_realm=apolo.local action=sip_auth section=directory

El Backend responde con XML conteniendo el A1 hash y configuracion:

<?xml version="1.0" encoding="UTF-8"?> <document type="freeswitch/xml"> <section name="directory"> <domain name="apolo.local"> <user id="1001"> <params> <param name="a1-hash" value="md5_hash_here"/> </params> <variables> <variable name="accountcode" value="ACC001"/> <variable name="user_context" value="from-pbx"/> </variables> </user> </domain> </section> </document>

3.3 Proceso de Autorizacion y Facturacion

Billing Engine - Flujo de Autorizacion
+=========================================================================+ | PROCESO DE AUTORIZACION DE LLAMADA | +=========================================================================+ 1. CHANNEL_CREATE Event +------------------------------------------------------------------+ | Billing Engine recibe evento ESL con: | | - caller_id_number (origen) | | - destination_number (destino) | | - context (from-pbx = outbound, to-kamailio = inbound) | +------------------------------------------------------------------+ | v 2. Account Lookup +------------------------------------------------------------------+ | Buscar cuenta por: | | - Outbound: caller_id_number -> accounts.codigo | | - Toll-free (0800): destination_number -> accounts.codigo | | - Inbound normal: SKIP (no billing) | +------------------------------------------------------------------+ | v 3. Rate Lookup (LPM - Longest Prefix Match) +------------------------------------------------------------------+ | Para destino "541156789012": | | | | Generar prefijos: | | ["5", "54", "541", "5411", "54115", "541156", ...] | | | | Query rate_cards: | | SELECT * FROM rate_cards | | WHERE destination_prefix IN (prefixes) | | AND effective_date <= NOW() | | AND (expiration_date IS NULL OR expiration_date > NOW()) | | ORDER BY LENGTH(destination_prefix) DESC, priority ASC | | LIMIT 1 | | | | Resultado: prefix="54115" -> rate=$0.05/min | +------------------------------------------------------------------+ | v 4. Balance Reservation +------------------------------------------------------------------+ | Formula de reserva: | | | | base_amount = rate_per_minute * 5 minutes | | buffer = base_amount * 8% | | total = CLAMP(base_amount + buffer, $0.30, $30.00) | | | | max_duration = (total / rate_per_minute) * 60 seconds | | | | INSERT INTO balance_reservations (...) | | UPDATE accounts SET balance = balance - total | +------------------------------------------------------------------+ | v 5. Authorization Response +------------------------------------------------------------------+ | Si OK: | | - Set channel var: max_duration_seconds | | - Set channel var: billing_rate | | - Allow call to proceed | | | | Si DENIED (insufficient balance, no rate, account disabled): | | - Hangup call with appropriate cause code | +------------------------------------------------------------------+

10.3 FreeSWITCH - Bypass Media (RTP NO procesado por FS)

CRITICO: Para que RTPEngine maneje TODO el flujo de media, FreeSWITCH debe configurarse con bypass_media para evitar que procese los paquetes RTP.
